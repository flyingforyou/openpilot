범위: Tesla Gap 연동 + tFollow 적용 + UI 표시로 한정 (Carrot 전체 롱컨트롤 포팅 아님).

차량: 사용자의 실제 Tesla Model X HW1. 테스트 디바이스: comma 4 ("mici" 하드웨어, 실제 해상도 536×240), SSH로 원격 접근.

코드 리뷰에서 발견/수정한 버그

FIXEDGap 미수신 시 Gap 1 자동 래치

CANParser는 메시지 미수신 시 모든 시그널을 0.0으로 초기화하는데, raw 0이 ACC_DIST_1(gap 1)로 디코딩됨 → 시동 직후 매번 가장 공격적인 1.10s로 시작하는 버그.

ts_nanos로 실제 수신 여부를 확인하도록 게이트 추가 (carstate.py).

FIXEDMPC solver reset() 시 slew 우회

reset()이 solver 실패 시에도 호출되는데, 이때 gap_adjust_initialized=False로 되돌아가 "최초 gap은 즉시 적용" 경로가 재무장됨 → 완만하게 올리던 tFollow가 한 번에 튐.

gap 상태를 reset()이 아닌 __init__으로 이동. 회귀 테스트로 고정.

개선재시동 간 Gap 값 유지 안 됨

DTR_Dist_Rq가 매번 재전송되는 신호인지 불확실 → 사용자 제안으로 LongitudinalPersonality와 동일한 패턴(TeslaLastGapAdjust Param)으로 마지막 값을 영속화.

CP.brand == "tesla"로 게이트해서 다른 차종에 stale 값이 새지 않도록 함.

FIXEDBlindspot: 초음파 신호 자체가 DBC에 없었음

기존엔 AutopilotStatus.DAS_blindSpotRearLeft/Right(message 921)만 사용 — 실제 로그로 확인해보니 이건 고속(41~74km/h)에서만 활성화되는 오토파일럿 차선변경 안전판단 신호였고, 계기판 초음파 아이콘과는 무관했음.

xnor-tech/tesla-unity 참고 포크에서 PARK_status2(message 782, ultrasonic) 신호를 발견 → 우리 DBC엔 이 메시지 자체가 통째로 빠져 있었음. 포팅해서 두 신호를 OR로 결합.

실제 어제 로그로 검증: message 782가 496프레임 존재, 왼쪽이 36프레임 동안 실제 WARNING으로 변함 — 살아있는 신호 확인됨.

Blindspot / Lead Source — 부분 검증됨 부분 확인

DAS (오토파일럿) 신호

실제 로그로 확인: 41~74km/h 구간에서 5회 활성화. 디코드 파이프라인 정상 동작 확인.

PARK (초음파) 신호

신규 추가 (message 782). 같은 로그에서 496프레임 존재, 왼쪽 36프레임 WARNING 확인. 아직 실차 재검증 전.

UI 렌더링 — Replay로 부분 확인

C++ tools/replay/replay가 이 fork의 SConstruct에 연결되어 있지 않아(tools/cabana만 포함됨), 대신 tools/replay/republish_route.py(간이 Python 리플레이어)를 만들어 실제 어제 로그를 msgq에 재발행하고 selfdrive.ui.ui를 RECORD=1로 캡처.

2초 지점 프레임에서 HUD(속도, MAX, 커브 인디케이터)는 정상 렌더링 확인. 8초 만에 캡처가 끊겨 R/V 라벨 · blindspot 점멸이 뜨는 순간까지는 아직 못 봄 — 재시도 중 디바이스 연결이 끊김 (No route to host).

새로 만든 디버그 도구

selfdrive/debug/tesla_gap_monitor.py

우리가 가정한 신호(STW_ACTN_RQ/DTR_Dist_Rq)만 감시하는 라이브 모니터. 신호가 맞다는 가정 하의 1차 검증용.

selfdrive/debug/tesla_gap_can_diff.py

가정 없이 버스 전체를 감시. 아날로그성(너무 자주 변함) 신호는 걸러내고, 스위치처럼 가끔·이산적으로 변하는 후보만 타임스탬프와 함께 출력. 진짜 gap 신호를 찾기 위한 핵심 도구.

tools/replay/republish_route.py

C++ replay 바이너리 없이도 녹화된 rlog를 msgq 버스에 재발행 — 실행 중인 selfdrive.ui.ui가 실제 주행처럼 인식하게 만드는 간이 리플레이어.

디바이스 관련 메모

  • comma 4 실제 해상도는 536×240 (2160×1080 아님) — HARDWARE.get_device_type()이 "mici"라 big_ui() 조건(tici/tizi)에 안 걸림. DRM 패널 native mode(240×536)로 재확인함.
  • Params 새 키(TeslaLastGapAdjust) 추가 시 scons 재빌드 필수 — params_keys.h가 Cython 익스텐션에 컴파일되어 들어감. capnp 스키마(car.capnp) 변경은 반대로 재빌드 불필요 (pycapnp가 런타임에 동적으로 읽음).
  • launch_chffrplus.sh를 그냥 실행하면 openpilot의 safe-overlay 업데이트가 트리거되어 /data/openpilot이 통째로 교체될 수 있음 — 한 번 실제로 겪었고 /data/safe_staging/old_openpilot에서 복구함. 재실행 후엔 꼭 git log로 브랜치 확인.
  • SSH 연결이 종종 불안정하게 끊김 (네트워크 문제로 추정). 오래 걸리는 작업은 nohup ... & disown으로 반드시 분리.
  • pytest는 디바이스에서 실행 가능 (capnp/numpy/pytest + 컴파일된 acados 솔버 모두 /usr/local/venv에 존재). 로컬 샌드박스는 아무 의존성도 없어서 이런 검증이 불가능했음.
