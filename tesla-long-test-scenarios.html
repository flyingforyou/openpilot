Tesla 저속 추종 튜닝 · 실차 테스트 시나리오

대상 기능 2종 — 기어가는 앞차 따라가기(LeadCreepFollowCms)와 앞차 움직임 따라 차간 조절(DynamicTFollowGain). 둘 다 기본 off이라 켜기 전엔 기존과 동일. 목표: "앞차 기어가는데 완전정지→크립으로 따라잡기"가 사라지는지, 부작용(추돌 위험·급감속·헌팅) 없는지 검증.
안전 규칙 (모든 시나리오 공통)
  • 뒤차 없는 한적한 도로/주차장에서 시작. 앞차는 내 차(테스트 협조자)가 이상적.
  • 발은 항상 브레이크 위. 이상하면 즉시 브레이크 → 해제. 새 롱 로직이니 첫 세션은 저속(≤30km/h)만.
  • 변경은 해제 상태에서만 반영됨(주행 중 목표거리 안 튐). 값 바꾸고 반영 → 한 번 해제 후 재engage.
  • 한 번에 한 노브만 바꿔서 A/B. 두 개 동시에 켜면 원인 분리가 안 됨.
사전 준비
1. 보드에서 cd /data/openpilot && git pull 로 이 커밋 받기.
2. params가 C++이라 sudo systemctl restart comma (매니저 전체 재시작).
3. 폰에서 http://<device-ip>:8088/live 열기 — 좌측에 source / 거리(dRel) / 앞차속도(vLead) 실시간 표시. 이걸 보면서 테스트.
4. 라우트명·시각 메모(로그 분석용). 드라이브 후 tools/tesla_analysis/pull_logs.sh로 회수.

A. 기어가는 앞차 따라가기 (LeadCreepFollowCms)

핵심: 앞차가 아직 움직이는데 완전정지 latch를 밟지 않게. 이게 체감이 가장 큼 → 먼저 테스트.
A-1가다 서다 크립 추종 (핵심 시나리오)
상황정체 구간. 앞차가 1~2 m/s로 조금씩 굴렀다 섰다 반복.
설정B: 0(off) → 한 바퀴 / A: 0.30 m/s 이상 → 같은 구간 다시
관찰/live에서 vLead가 0.3~1 m/s일 때 내 차가 완전정지(standstill)로 latch되는지 vs 저속으로 함께 구르는지. 몸으로는 "섰다 크립" 덜컹임이 사라지는지.
합격A에서 앞차 기어갈 때 완전정지 없이 저속 롤링, 재출발 덜컹임 감소. 불합격: 앞차에 계속 붙어감/거리 안 벌어짐, 또는 헌팅(가속·감속 진동).
A-2앞차 실제 완전정지 (안전 회귀 확인)
상황앞차가 신호/정체로 완전히 멈춤(vLead→0).
설정A: 0.30 켠 상태
관찰vLead가 임계(0.3) 밑으로 내려가면 정상적으로 완전정지하는지. 정지 거리(dRel)가 off일 때와 같은지.
합격앞차가 서면 내 차도 정상 정지, 정지 거리 동일. 불합격: 앞차 섰는데 안 서고 계속 기어감 → 즉시 브레이크, 임계값 상향 또는 off.
A-3정지 상태 → 앞차 출발
상황둘 다 정지 → 앞차가 스르륵 출발.
관찰off일 때의 "완전정지 hold → 갭 벌어짐 → 크립 재출발" 지연이, A에서 줄거나 사라지는지.
합격재출발이 더 즉각적/매끄러움.
임계값 튜닝 가이드
  • 0.30: 아주 느린 크립까지 따라감(가장 매끄럽지만 앞차 정지 판단이 늦을 수 있음).
  • 0.50: 균형. 확실히 움직일 때만 따라감.
  • 0.80: 보수적. 어지간히 움직여야 완전정지 안 함.
  • 앞차 정지인데 안 서는 느낌이면 임계값 올리기. 여전히 덜컹이면 내리기.

B. 앞차 움직임 따라 차간 조절 (DynamicTFollowGain)

핵심: 앞차 저크(가감속 변화)에 맞춰 차간을 실시간 조절 → 추종/재출발 부드러움 보강. A와 별개로 A/B.
B-1앞차 감속 반응
상황정속 추종 중 앞차가 감속 시작.
설정B: 0 → 반복 / A: 0.50초
관찰A에서 앞차 감속 시 차간을 미리 벌려 부드럽게 받는지(급브레이크 감소). 과하게 벌어져 뒤처지지 않는지.
합격감속 받아치기가 부드러움, 급제동 빈도 감소. 불합격: 과감속/뒤처짐 → gain 낮추기.
B-2앞차 가속(풀어줌) 반응
상황정체 풀리며 앞차 가속.
관찰A에서 차간을 일시적으로 줄여 더 민첩하게 따라붙는지. 너무 바짝 붙지 않는지.
합격따라붙음이 민첩·매끄러움, 거리 과도하게 안 벌어짐.
주의 — B(dynamic t_follow)는 과도 신호(transient)라 앞차가 등속/등가속에 도달하면 차간이 base(선택한 Gap)로 복귀함. 정상. 정속 추종 중엔 효과 거의 없고 가감속 변화 순간에만 작동.

C. 병행 테스트 (A+B 함께)

설정A 0.30~0.50 + B 0.50초 동시 ON
구간정체 가다 서다 왕복 1회.
관찰"완전정지→크립 따라잡기"가 사라지고(A) 추종이 매끄러운지(B). 헌팅/추돌감 없음.
목표carrot 저속 추종 느낌에 근접 — 앞차와 함께 롤링, 재출발 부드러움.

D. 회귀 확인 (반드시)

  • off = 무변화: 두 노브 모두 0이면 예전과 완전히 동일해야 함. 평소 주행이 달라졌다면 배선 문제 → 보고.
  • 일반 정지: 신호등·정지선 앞 리드 없는 정지가 정상인지(A는 리드 있을 때만 작동, 신호 정지엔 영향 없어야).
  • 고속 추종: 고속에서 차간·가감속이 기존과 동일한지(두 기능 다 저속/전이 상황용).
  • 컷인: 옆 차선 차가 끼어들 때 과민 반응 없는지.

E. 로그 분석 (드라이브 후)

tools/tesla_analysis/pull_logs.sh <route> 로 세그먼트 회수.
정지 이벤트별 vEgo·dRel·vLead·standstill·accelCmd 시계열을 뽑아 off vs on 비교. 확인 포인트:
  • on에서 vLead>임계 구간에 standstill이 latch되지 않는가(A 효과).
  • 완전정지→재출발 사이 크립 지연이 줄었는가.
  • 앞차 감속 시 accelCmd가 더 이르고 완만한가(B 효과).
  • 부작용: dRel이 위험하게 짧아지는 순간, accelCmd 진동(헌팅) 없는지.
※ 오늘/어제 차가 다르면(Car A/B) 레이더 캘리가 달라 raw dRel 직접 비교 주의.
기록: 각 시나리오마다 라우트명 · 노브값 · 합격/불합격 · 한 줄 소감을 남기면 다음 튜닝이 빨라짐.
