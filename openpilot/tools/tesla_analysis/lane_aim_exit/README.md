## 부호 (반드시 이대로)

- `controlsState.curvature`, `carControl.actuators.curvature` **양수 = 오른쪽 코너** (GPS 방위각 변화율과 상관 +0.63/+0.83,
  먼 지점 차선 휨과 +0.97). `carState.steeringAngleDeg`와는 반대 부호(−0.997).
- 차선/위치 y: **오른쪽 양수** (`laneLines[0..3].y[0]` ≈ −5.3, −1.7, +1.7, +5.2).
- `laneAimShift` 양수 = 가상 카메라를 오른쪽으로 → 모델이 차가 더 오른쪽에 있다고 봄 → **차를 왼쪽으로 보냄**.
  "차를 미는 방향(+오른쪽)" = `−laneAimShift`.
- 차선 안 위치(+ = 차가 중앙보다 오른쪽) = `−(laneLines[1].y[0] + laneLines[2].y[0]) / 2` (도로 좌표, to_road_frame 이후).
  모델이 보는 자기 위치 = 그 값 + `laneAimShift`.

## 확인된 사실 (11/15 주행 0272–0277, rlog 20 Hz / qlog 2 Hz)

1. 코너 안: 차는 안쪽 0.03–0.13 m (기능 전 0.22 m). 이동량은 바깥으로 민다(설계대로). 11건 중 2건은 상한 `AIM_MAX` 0.30에 붙고도 안쪽 0.31–0.34 m.
2. **코너가 풀리기 시작할 때(|횡가속도| < 코너 중앙값의 60%) 11/11건 모두 이동량이 바깥으로 0.07–0.30 m 밀고 있음** →
   0.7–5 s 안에 바깥으로 0.13–0.60 m 밀림. 이동량 크기 vs 밀림 크기 상관은 0.28(약함, 다른 요인 섞임).
3. 기능 전(11/13 0026e/026f/0270, 코너 홀드 켜졌을 수 있음, 도로 다름) vs 후: 탈출 후 5 s 최대 치우침 중앙값 0.23 → 0.33 m,
   0.3 m 초과 22% → 57–70%, 바깥 방향 7/11 → 17/17.
4. 원인 구조 (`lane_aim.py`):
   - 이동량이 곡률과 연결 안 됨 — 위치 오차 적분이라 코너가 끝나도 남음. 모델의 안쪽 쏠림은 곡률과 함께 즉시 사라짐.
   - 누설 `AIM_LEAK_TAU` 20 s가 코너/직선 동일 (docstring의 "직선에서 빠진다"와 다름). 빠른 해제(1.5 s)는 깜빡이/차선변경/조향 꺼짐/차선 불확실만.
   - `AIM_DEADBAND` 0.08 m 안에서는 적분 정지, 밖에서도 `AIM_GAIN` 0.6/s로 느림 → 차가 밀린 뒤에야 풀리고 반대로 넘어가기도 함.
   - 진입 지연으로 차가 잠깐 바깥에 있으면 그것도 적분해 버림(진입 과도 응답을 적분).
5. S자 연속 코너(0272 489 s, 0273 677 s; 120 km/h, 간격 3–4 s): 앞 코너의 이동량이 다음 코너에서 **안쪽으로 미는 방향**으로 이월 →
   진입에서 파고듦, 반전에 2 s+, 0273은 둘째 코너 탈출에서 바깥 0.60 m. 헤어핀은 9 m/s 이하라 `AIM_MIN_V` 10 m/s 미만(실측 없음).
6. 검증 공백: `lateral_windows.txt` 중 기기에 남은 3개(026f--21, 0270--7, 0270--10)는 모두 코너 끝 직전(35.0 vs 35.5 s, 40.0 vs 40.7 s)
   또는 코너 한가운데(23 vs 32.7 s)에서 끝남. `latsim.metrics`는 코너 구간 평균(inside/swing/jerk)뿐 → 탈출 쏠림은 측정 대상이 아니었음.
   0261–026b 6개는 기기에서 삭제돼 미확인.

## 수정 (2026-11-15 적용, 커밋 전 · 실차 미확인)

`lane_aim.py`: 이동량을 모델 계획의 횡가속도에 묶음. `lat_accel_ahead(modelV2)`가 지금~`AIM_LOOKAHEAD` 2.0 s 앞까지
계획(`orientationRate.z × velocity.x`, + = 오른쪽 코너, `controlsState.curvature`와 상관 0.995)의 최소/최대를 주고,
`LaneAim.update(..., lat_ahead)`가 이동량을 **그 구간 내내 유지되는 코너의 바깥 방향으로만, `AIM_PER_LAT` 0.20 m per m/s² 이내**로 제한.

- 탈출이 계획에 들어오면(2 s 전) 한도가 줄어 이동량이 `AIM_BOUND_TAU` 0.4 s로 따라 내려감(끊지 않음).
- 앞쪽 부호가 바뀌면(S자) 한도 0 → 다음 코너 전에 비워짐. 직선에서는 이동량 0 (직선 치우침은 차선 트림 몫).
- 진입도 같은 규칙: 코너가 계획 전체에 자리잡기 전에는 쌓이지 않음(진입 과도 응답 적분 방지).
- `modeld.py`, `latsim.py`는 인자만 추가. 단위 테스트 `test_lane_aim.py::TestTheShiftBelongsToTheBend`.

오프라인 재생(`replay_aim.py`, 11/15 깨끗한 탈출 11건, 기록 → 재생):
탈출 시점 바깥으로 미는 이동량 0.179 → 0.015 m, 탈출 후 5 s 바깥 최대 중앙값 0.34 → 0.20 m(기능 전 0.23), 최악 0.61 → 0.52,
0.3 m 초과 7 → 4건, 코너 안쪽 평균 0.11 → 0.10 m(유지). S자(0272 489 s, 0273 677 s) 이월 −0.16 → 0.00.
**위치 수치는 추정** — 모델을 돌리지 않고 "차는 이동량 변화를 0.3 s 지연 + 1.2 s 시정수로 따라간다"고 가정(0.7–2.0 s로 바꿔도 중앙값 0.19–0.23).
이동량 수치는 실제 코드 그대로.

## 원인 검증 (11/16, rlog 20 Hz — 모델 계획과 직접 대조)

탈출 순간 모델 계획(`position`)이 1–3 s 뒤 차선 중앙 대비 어디를 향하는지(바깥 +, 도로 좌표)를 봄. rlog: 기본 0261--19/20, 0264--29/30,
0265--7~12(`rlog-plain/`), 홀드 026f/0270, 에임 0272/0273.

| 설정 | 탈출 때 남은 이동량(바깥) | 모델 계획 @1/2/3 s | 실제 바깥 최대 |
|---|---|---|---|
| 기본 (깨끗한 5건) | 0 | +0.03 / +0.09 / +0.11 | 3 s 안 −0.03 ~ +0.19 m |
| 에임, 수정 전 (8건) | +0.13 ~ +0.30 | +0.21 / +0.23 / +0.20 (심한 3건 +0.3 ~ +0.5) | +0.13 ~ +0.52 m |

- 에임 주행의 계획(도로 좌표) ≈ 모델 자체 계획(+0.1) + 남은 이동량. 모델이 본 화면 기준으로는 중앙 근처로 가려는 것 → **기본 대비 초과분은 남은 이동량 그대로**.
  따라서 수정(탈출 2 s 전부터 이동량 제거) 후 기대치는 기본 수준(+0.15 ~ 0.2 m, 선까지 0.55 m 이상). 재생 가정 GAIN=1.0이 타당하고,
  회귀로 맞춘 0.3(R² 0.17)은 이동량이 위치 오차에서 만들어지는 되먹임 때문에 낮게 나온 것으로 봄.
- 차의 곡률은 차 위치의 차선 곡률과 ±0.2 s 안에서 같이 풀림 — "차가 못 따라가서"가 아님. 감쇠 가드는 모델 계획(+0.2 바깥)과 싸우게 되어 넣지 않음.
- qlog 비교에서 기본 0261이 선에 닿은 것으로 본 건 오류: 옆 속도 6.5 m/s, 계획 −2 ~ −3 m인 차선 이동/선 재인식 구간이었음(2 Hz 분석은 이를 못 거름).
  기본의 늦은 0.9–1.05 m(탈출 4–6 s 뒤)도 다음 굽이/선 점프.
- 남는 것: 모델 자체의 넓은 탈출(+0.15 m 안팎)은 그대로. 실차 미확인.
